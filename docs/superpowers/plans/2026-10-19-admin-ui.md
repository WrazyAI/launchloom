# Operations Studio Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement approved direction A in existing LaunchLoom colors, connected to real shared client/attempt/profile APIs with accessible responsive interactions.

**Architecture:** Compile an independent React/TypeScript admin entry using direct pinned esbuild and package only data-free assets with the existing Worker under a separate `ADMIN_STATIC` binding. Keep the same admin origin and compatible invitation route; private API data stays behind `requireAdmin`. The public Astro site and generated-client styling remain unchanged.

**Tech Stack:** Existing React/TypeScript, scoped CSS, planned build-only esbuild, Worker static-assets binding, licensed self-hosted Manrope/Source Sans 3, Vitest and Playwright.

**Spec:** `docs/superpowers/specs/2026-10-19-admin-workspace-design.md`; master contracts/rollout `docs/superpowers/plans/2026-10-19-admin-workspace.md`.

## Global Constraints

- A's vertical operations layout, not B; forest `#10251f`, muted `#587069`, canvas `#f4f2ea`, paper `#fffefa`, sage `#bad8c8`, lime `#d9f06b`, divider `#d9ddd1`.
- Admin styling is scoped; public/global CSS, public logo and generated-client templates are not redesigned.
- All authorized admins see all clients, invitations and generation attempts; filters do not imply ownership isolation.
- Separate execution from delivery, actual/estimated/unreported costs and creator from initiator.
- No fictional seed data, invented metrics, active GHL integration, new rerun buttons or signup-admin shortcut in production.
- Master Global Constraints, wire types and Accounts `requireAdmin` apply verbatim.

## Review Focus

1. Static fallback or direct asset/HTML paths must not bypass Worker authorization or expose records (Task 1).
2. Focus/selection/deep links must survive filters, refreshes and slow/stale responses without showing the wrong client's detail (Task 2).
3. Unicode names, malformed dates, unknown actors/costs and diagnostic delivery must remain readable and honest (Task 2).
4. Single-use invite links, enrollment tokens and signed evidence URLs must not leak through query/history/logs, clipboard retries or bundles (Task 3).
5. Keyboard/mobile/error/empty states and unavailable auth must not trap users, hide failures or silently look successful (Tasks 1–3).

## Task 7: Build and serve a data-free same-origin admin shell

**Files:** Create `src/admin/{main.tsx,AdminApp.tsx,styles.css,api.ts,route-state.ts}`, `scripts/build-admin-workspace.mjs`, `worker/src/admin/{asset-handler,router}.ts`, `tests/admin-asset-build.test.ts`, `worker/test/admin-assets.test.ts`; modify `worker/src/admin-dashboard.ts`, `worker/src/index.ts`, `wrangler.jsonc`, `package.json`, lockfile, `.gitignore`, Worker TS configs and generated types. Fonts/licenses: create `src/admin/fonts/` only after provenance/license review; no public-site font replacement.

**Interfaces:** `buildAdminWorkspace({outDir,production}):Promise<{files:string[],sourceDigest:string}>` emits only `worker/admin-dist/admin-assets/app.js`, `app.css`, bounded imported chunks and fonts/licenses. `renderAdminDashboardHtml()` becomes a no-data shell loading those files; a separate data-free login shell uses the same entry at `/admin/login`. `serveAdminAsset(request,env):Promise<Response|null>` only serves allowlisted built `/admin-assets/*` files via `env.ADMIN_STATIC.fetch`; no HTML fallback. `routeAdminRequest(request,env,ctx):Promise<Response|null>` protects workspace HTML/APIs and returns a relative login redirect or the appropriate JSON status. `fetchAdmin<T>(path,init?):Promise<T>` centralizes same-origin credentials/no-store/error mapping; no tokens in localStorage. `readRouteState(url):AdminRouteState`/`writeRouteState(state):URL` cover view/client/attempt/filter/cursor. `AdminRouteState` uses shared query types plus `view:'generations'|'clients'|'invitations'|'team'|'integrations'|'settings'` and selected IDs.

## Task 9: Invitations, team/accounts, login and GHL placeholder

**Files:** Create `src/admin/{InvitationsView,TeamView,ProfileView,SignInView,EnrollmentView,IntegrationsView}.tsx`, `tests/admin-account-flows-browser.test.ts`, `tests/admin-invite-flows-browser.test.ts`; modify `src/admin/{AdminApp,WorkspaceShell}.tsx`, `styles.css`, `api.ts`, `route-state.ts`, `worker/test/{onboarding-admin,generation-admin}.test.ts` for new shell assertions (retain all auth/security assertions).

**Interfaces:** Extend `AdminApi` with `listInvites`, legacy `createInvite/revokeInvite/recoverIntake`, membership `getTeam/createEnrollment/changeMember/updateOwnProfile/acceptEnrollment`, auth `signIn/signOut/requestPasswordReset/resetPassword/verifyEmail` through Accounts allowlisted proxy. Components never get DB credentials or provider-admin methods. Enrollment bearer is received in `#enroll=<token>`, promptly moved into a short-lived HttpOnly pending-enrollment cookie through a same-origin bounded POST and removed from history; no localStorage/query/log/analytics transmission. The token itself is not an admin session and can only be claimed with matching verified provider identity.
